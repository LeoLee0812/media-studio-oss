# 写作风格系统

## 注册表 `lib/styles.ts`
内置一种风格：
- `default` —— 客观科普调性，小标题分节，1500-3000 字

一个 StyleDef 能做：声明适用平台（`appliesTo`）、注入风格总纲、替换某平台的平台规范、停用冲突的通用提示词、覆盖 schema 的字数/排版约束、成稿后确定性净化。

> **加新风格只加 StyleDef + 注册提示词，生成链路不用动。**

## 收口 `lib/styled-generate.ts`（硬性约定）
凡是**模型输出会成为稿件标题/正文**的 generateObject 调用，一律走 `styledGenerateObject`。finalCheck 追加和成稿净化由它统一负责，**不许在调用点手工织入**——曾经 AI 修改 / AI 标题两条路径就是手工织入漏掉了净化。新增出稿路径（续写/润色等）也必须走它。

## 风格只在适用平台生效
风格可声明 `appliesTo` 平台白名单，白名单外的平台经 `effectiveStyle()` 自动退回默认（长文风格的「句式断裂至少 3 次」这类条款塞给短文平台是自相矛盾的指令）。

`ms_drafts.meta.style` 记录的是**生效风格**，由 `generate.ts` 写入，各 API 路由不要自己塞。稿件页 AI 修改 / AI 标题据此沿用同一风格（都走收口，净化不漏），避免改一次就漂回默认调性。

## 开关三处
1. 选题页生成卡片（逐篇选）
2. 洗稿页
3. 设置页存全局默认（`app_config.writingStyle`，前两处的初始值）

## 自定义风格的两个经验（实测踩出来的）

### 1. 提示词压不住机械禁令
四五千字长文里，标点/禁用词类的硬禁令靠提示词只能压低概率、压不到零。对策是给 StyleDef 挂 `sanitize` **确定性净化**：
- 只作用于正文，参考来源节排除在外
- **代码段不洗**（围栏/行内代码里的引号冒号是语法）
- 禁用词替换表要**顺序敏感**，长模式必须排在其子串模式前面，否则会洗出病句

### 2. 模型会编造第一人称经历
叙事型风格（调查实验型/产品体验型）天生要求亲自下场，素材里没经历时模型必然编一个（编「我实测了」「我朋友说」，甚至编出处）。加禁令没用，因为禁令和风格在打架。

**正解是换骨架**：「真实经历」栏为空时注入 `noExperienceHint`，把文章原型锁定到不依赖亲身下场的「现象解读型」（观察 → 好奇 → 追问 → 升维），活人感改由态度和判断来扛。实测后虚构经历归零。

## 「真实经历」是独立字段
生成卡片 / 洗稿页各有「真实经历」和「附加指令」两个框。**防编造的判定只看经历栏**——附加指令是自由指令（「标题带上 XX」），写了不代表给了经历，别再用它做判定信号。

**虚构红线在任何风格下都生效。** 要让稿子有真实的第一手经历，就写进「真实经历」栏；写了就织进正文，没写就走现象解读型，不编造。
