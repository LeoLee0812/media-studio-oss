# 本地笔记批量导入（Obsidian vault → 素材流）

把一个本地文件夹里的 Markdown 笔记整批灌进素材流，之后走和 RSS 素材完全一样的
「立选题 → 调研 → 母稿 → 成稿」流程。

入口：素材流页 →「添加素材」→「批量导入」标签页。

## 三种投喂方式

| 方式 | 说明 |
| --- | --- |
| 拖拽 | 把文件夹（或若干笔记文件）直接拖进弹窗的虚线框。目录用 `webkitGetAsEntry()` 递归展开，子目录一并收 |
| 选择文件夹 | 走 `<input webkitdirectory>`，选中的目录整棵递归 |
| 选择文件 | 普通多选，适合只导几篇 |

三条路最终都归到同一个函数：把「相对路径 + File」列表解析成待导入条目。

## 收哪些、跳哪些

- **只收**：`.md` / `.markdown` / `.mdx` / `.txt`
- **跳过**：`.obsidian`、`.trash`、`.git`、`.vscode`、`.idea`、`node_modules`、`__pycache__`，
  以及任何以 `.` 开头的目录/文件；图片、PDF、HTML 附件因为不在扩展名白名单里天然被排除
- **上限**：单次最多 2000 个文件；单篇正文超 20000 字截断（末尾标「正文已截断」）；空文件跳过

跳过的数量会在预览区提示（「已跳过 N 个非笔记文件」）。

## 每篇笔记解析成什么

| 素材字段 | 取值规则 |
| --- | --- |
| 标题 | frontmatter `title` → 正文第一个一级标题 → 文件名（去扩展名） |
| 正文 | 文件原文（含 frontmatter，保留原貌方便后续洗稿） |
| 摘要 | 正文剥掉代码块 / 标题号 / 链接图片语法 / 引用符后的前 140 字 |
| 标签 | frontmatter `tags`（列表或逗号串）+ 正文里的 Obsidian 行内标签 `#tag`，去重后最多 12 个 |
| 板块 | 相对 vault 根的**首层目录名**（如 `wiki/xx.md` → `wiki`）；根目录下的笔记为未分类。可在弹窗里填「统一板块」覆盖整批 |
| 原文链接 | frontmatter `source` / `url`，且必须是 http(s) 开头才收（剪藏类笔记常带） |
| 发布时间 | frontmatter `date` / `created`，解析不出来就留空（不猜） |
| 来源 | 固定 `local`（素材流「全部来源」筛选里叫「本地导入」） |

frontmatter 解析器是刻意做窄的极简实现：只认 `key: value`、缩进 `- item` 列表、`[a, b]` 内联数组
——Obsidian 的 frontmatter 99% 是这三种形态，认不出来的键直接忽略，绝不抛错让整批导入失败。

## 去重与幂等

去重键是 `local:<vault 名>/<库内相对路径>`，落在 `ms_materials.dedupe_key` 唯一索引上。

- vault 名取这批文件的公共首层目录名（拖一个文件夹进来就是文件夹名）
- 同一份 vault 重复导入：已存在的条目原样跳过，**不覆盖**已有素材（你可能已经改过它的板块/状态）
- 结果按「新增 N 条 / 跳过 N 条 / 失败 N 条」汇总

改笔记内容后想重新灌？先在素材流里删掉旧条目，或换个 vault 名导入。

## 数据流与隐私边界

```
本地文件夹 ──浏览器 File API 本地读取解析──> 预览列表（可逐条剔除）
        └──分批 POST（每批 50 条）──> /api/materials/bulk ──> 你自己的 ms_materials 表
```

- 文件**不上传原始文件**，是在浏览器里解析成结构化条目后发的；全程只跟你自己这份部署通信
- 公开演示站是只读模式（`READ_ONLY=1`），middleware 把所有非 GET 请求拦成 403，
  所以演示站上这个功能点了也导不进去——要用就自部署
- 大目录分批提交，界面显示 `已导入 / 总数` 进度，中途失败前面已入库的不回滚
