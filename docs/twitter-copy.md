# 一键复制到推特长篇 X Articles（2026-07-29 起）

公众号稿件页「推特长篇」按钮：把同一篇公众号稿转成 X 的「文章（Articles）」编辑器
（`x.com/compose/articles/edit/<id>`）吃得下的格式。**不影响原有的公众号 / 小红书 / 抖音三个按钮**，
四条路各走各的 HTML。

## X 文章编辑器的真实 schema（2026-07-29 实证，不是推测）

X 的文章编辑器是 **Draft.js**（X 自己 fork 的 `twitter-forks/draft-js`）。
DOM 特征：`public-DraftEditor-content` / `DraftEditor-editorContainer`，块类型全部带 `longform-` 前缀。
在真实文章编辑器里派发 paste 事件、逐个标签测出来的规则：

| 输入 | 结果 |
| --- | --- |
| `h1` | ✅ → `longform-header-one`（工具栏「正文」下拉里的**大标题**） |
| `h2` | ✅ → `longform-header-two`（**小标题**） |
| `h3` 及以下 | ⬇️ 降级成普通段落 |
| `p` | ✅ → `longform-unstyled`，连续 `<p>` 各成一块 |
| `blockquote`（裸文字或包 `p` 都行） | ✅ → `longform-blockquote` |
| `ul/ol` + `li`（`li` 里包 `p` 也认） | ✅ → `longform-*-list-item` |
| `strong`/`b` · `em`/`i` · `del`/`s` · `a[href]` | ✅ 加粗 / 斜体 / 删除线 / 链接全部保留 |
| `code` · `pre` · `mark` · `u` · `sup`/`sub` | ❌ 剥成纯文本 |
| `hr` | ❌ 直接丢弃（分隔线只能在编辑器里走「插入」菜单） |
| `<p><br></p>` 空段落 | ❌ 丢弃（想靠空段落造留白是白费） |
| `img`（外链） | ❌ 粘不进去，X 只留下一个孤零零的 📷 字符，连 `alt` 都不保留 |
| 内联 `style`（颜色 / 字号 / 行距） | ❌ 一概被剥；唯一例外是 `font-weight:bold\|700` 会被认成加粗 |
| **`section` / `div` 外壳** | ☠️ **把内部所有块压塌成一个大段落** |
| `text/plain` 里的 Markdown 符号 | ❌ 完全不解析，`## x`、`**x**` 原样显示成字面量 |

最后两条是整个功能的设计前提：

1. **公众号那份 HTML 绝不能直接复用**。它满是 `<section style>`，Draft.js 的
   `convertFromHTMLToContentBlocks` 认不出这个块级容器，会把里面的标题、段落、引用
   全部压成**一个**段落、靠软换行 `\n` 挤在一起——这就是「公众号那套直接粘到 X 上是一坨」的根因。
   所以 `lib/twitter-article.ts` 的产物顶层必须是**裸标签**，容器一个都不能留。
2. **纯文本通道不能带 md 记号**。`text/plain` 兜底那份必须是已经排好版的文本。

## 风格「对齐公众号」能对齐到什么程度

X 不给内联样式，所以**主题色、字号、行距一概带不过去，只能对齐结构**：

| 公众号那边 | X 这边 |
| --- | --- |
| 一段 1~2 句（`reflowProse`） | ✅ 同一个函数，同一个节奏 |
| `##` 小标题分节 | ✅ → 大标题；`###`+ → 小标题 |
| `**加粗**` 强调 | ✅ 原样保留 |
| 引用块 / 列表 | ✅ 原样保留 |
| 主题色 / 字号 / 行距 / 边框装饰 | ❌ 全部丢失，X 只有自己那套排版 |
| 配图随粘贴自动转存 | ❌ X 没有这个机制，只能手动上传 |

## 转换规则（`lib/twitter-article.ts`）

- **参考资料段剔除**：复用 `stripReferences()`，跟另外三个平台一致。
- **正文重排**：复用 `reflowProse()`，长段落按句末标点切成「每段 1~2 句」。
  X 信息流的读者比公众号更没耐心，长段落是劝退主因，默认开。
- **标题就近提升**：`#`/`##` → `h1`（X 大标题），`###` 及以下 → `h2`（X 小标题）。
  X 只有两级标题，这样两级都用上，没有一层白白被降级成正文。
- **图片 → 提示行**：原位换成「📷 配图N：图注」，复制完 UI 会提示要在 X 里手动传几张。
- **分隔线 → `· · ·`**：`<hr>` 会被丢弃，换成一行居中符号才留得住。
- **代码块 / 表格 → 普通段落**：X 没有对应块型，保文字。
- **脱掉所有块级容器**：`section`/`div`/`article`/`main`/`aside`… 从里往外脱最多 8 层。
- **清掉所有属性，只留 `<a href>`**。

## 交互

点了即刻写剪贴板，**不需要等 AI**（不像小红书要先跑高亮/emoji 生成）。
提示条会报「切了几段 · 几个小标题 · 几张配图要手动上传」。

粘贴步骤：X 侧栏「文章」→「撰写」→ 光标点进正文 → `Cmd+V`。**标题在 X 的「添加标题」里另填**，
封面图也在 X 端单独传（X 建议 5:2 宽高比）。

## 已知瑕疵（跨平台共有，不是本功能引入的）

marked 走 CommonMark 的强调定界符规则，对中文不友好：`一个叫**中缝核（Raphe Nuclei）**的地方`
里的 `**` 因为紧邻中文/全角标点无法配对，加粗失效、`**` 直接漏成字面量。
**公众号预览里同样会漏**，两边表现一致。要修得在 marked 那一层统一处理，属于独立改动。
