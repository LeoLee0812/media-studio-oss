# 一键复制到抖音长文（2026-07-20 起）

公众号稿件页头部「抖音长文」按钮：展开一个三段式导出面板，把同一篇公众号稿转成
「抖音创作者中心 - 发布文章」（2025-12-26 正式上线）能直接用的内容。
**不影响原有的「复制到公众号 / 小红书」两条路**，各走各的转换。

## 为什么是「三个独立复制 + 纯文本正文」

抖音发布页（creator.douyin.com/creator-micro/content/post/article）是三个**分离输入框**：
文章标题、文章摘要、文章正文。用户是分别粘 3 次，所以面板做三个独立复制按钮，不拼成一坨。

正文复制走**和公众号完全同一套富文本剪贴板**（`text/html` + `text/plain` 兜底）：实测（用户确认）
抖音正文编辑器和公众号一样，粘贴富文本时会自动把外链 `<img>` 转存过去——所以**图片随粘贴带过来**，
不用手动上传。`text/plain` 通道放 `lib/douyin.ts` 转出的结构化纯文本，只在目标仅吃纯文本时兜底
（此时图片带不过去，用「【配图N】」占位提醒）。标题、摘要是普通 input，仍走纯文本复制。

## 字段约束（2026-07-20 调研，平台常灰度，上线前以实际发布页 maxLength 为准）

| 字段 | 上限/区间 | 处理 |
| --- | --- | --- |
| 文章标题 | ≤30 字 | 纯文本，面板显示 `x/30`，超了标红 |
| 文章摘要 | ≤30 字（硬 maxLength） | AI 生成 3 候选，逐条 `x/30`，服务端超 30 按码点硬截 |
| 文章正文 | 300–8000 字 | 富文本复制（同公众号），面板提醒过短/超长 |
| 配图 | ≤30 张 | 随富文本粘贴自动转存（同公众号）；纯文本兜底通道才留「【配图N】」占位 |

**计数一律用 `Array.from(str).length`（Unicode 码点）**，不是 `str.length`——后者会把 emoji/代理对
算成 2，与抖音计数器口径不符。

## 正文纯文本兜底转换（`lib/douyin.ts` `renderDouyinBody`）

> 这是 `text/plain` 兜底通道；正文主通道是公众号的富文本 HTML（带图）。下列规则只作用于纯文本兜底。

纯函数、前后端通用、不依赖 DOM：
- 小标题 `#{1,6}` → 纯文本行（抖音靠段落 + 空行体现层级，不留 `#`）
- 加粗 `**x**` / 斜体 / 行内代码 → 脱标记保文字（抖音正文无稳定的行内强调）
- 超链接 `[文字](url)` → 只留文字（url 抖音正文不支持）
- 图片 `![alt](url)` → 「【配图N：图注】」占位行，`imageCount` 计数
- 分隔线 → 「· · ·」；无序列表 → 「· 」；有序列表保留序号
- 收敛连续空行到最多一个，去首尾空行

## 摘要生成（`/api/drafts/[id]/douyin-summary`）

摘要是信息流里标题之外的第二个钩子拦截点，唯一任务是「在读正文前制造非点开不可的认知缺口」。
- 一次给 **3 个 ≤30 字候选**，角度错开（信息差/冲突/结果承诺/悬念/戳痛点/数字疑问/反常识）。
- 走 `getFlashModel` + `getPrompt("douyin_summary_system")`（可在 /prompts 页改）。
- **不用小红书那套缓存/并发锁/预热机制**：摘要输出极短、几秒出结果，点一次现生成即可
  （小红书那套是给 100 秒长文高亮兜底的，这里没必要）。
- 服务端清洗：去行首编号、去整句书名号/引号包裹、超 30 字按码点硬截。
- 不落稿件正文：摘要只用于用户手动填进抖音发布页。

## 发布页手动补项

话题 #、原创/自主声明、合集、头图/封面、背景音乐——这些是抖音发布页的开关/表单项，
无法靠正文文本携带，面板底部有一行静态清单提醒。
