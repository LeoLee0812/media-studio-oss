# 封面模板参考图

「模板直生」链路的参考图库：生成封面时，服务端把对应风格目录下的图片（最多 4 张，按文件名排序）
连同固定指令（提示词中心「模板直生指令」）+ 该风格的「风格定义」一起发给 GPT Image 的
`/images/edits`，让图像模型照模板的风格自己构思新封面——不经过文案引擎写提示词。

## 模板图是可选增强，不是风格的前提

风格由 `prompts/system/cover/styles/<key>.md`（风格定义）用文字立起来，没有模板图的风格
走「锚点直生」：通用版式骨架 + 风格定义 + 结构化字段 → `/images/generations`。
往下面的目录里丢图，同一套风格就自动从锚点直生升级成模板直生，风格定义不用改。

## 怎么加模板

把参考封面图（png / jpg / webp）丢进对应风格的子目录，随代码部署即生效：

```
templates/
  viral_tech/       爆款科技风（暂无模板 → 锚点直生）
  mono_system/      黑白系统风（暂无模板 → 锚点直生）
  material_type/    语义字体风（暂无模板 → 锚点直生）
  crowd_type/       人群造字风（暂无模板 → 锚点直生）
  glass_blob/       玻璃气泡风（暂无模板 → 锚点直生）
  timeline_mini/    时间微缩风（暂无模板 → 锚点直生）
```

目录不存在或为空都不影响使用，前端会自动把该风格显示成锚点直生。

## 硬约束

两条链路的画面约束分别写在提示词页可改的两份指令里，都要求封面底部 10% 是干净留白带
（无文字、无图画，深色浅色都行）：
- 模板直生 → 「模板直生指令」（`cover-template-instruction.md`）
- 锚点直生 → 「锚点直生版式骨架」（`cover-anchor-layout.md`），另含标题唯一、宽幅左右分栏等通用规则。

另一条跨链路的硬规则：**封面一律不生成刊头**（不许出现刊名、博主名、账号名、logo、水印），
参考图里带的博主名也不许照抄——所以往上面目录里丢模板图时，图里有刊头无所谓，模型不会抄。
